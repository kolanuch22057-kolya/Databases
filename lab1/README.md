# Лабораторна робота 1

Мета системи

Дана система призначена для керування процесом прокату фільмів у відеопрокаті або онлайн-сервісі. Вона дозволяє вести облік фільмів, клієнтів, оформлених прокатів та оплат.

Система забезпечує можливість реєстрації клієнтів, перегляду доступних фільмів, оформлення прокату фільмів та фіксації платежів.

Ключові елементи даних

Клієнти можуть брати фільми в прокат, оформлюючи відповідні записи.
Фільми доступні для прокату, якщо вони не зайняті.
Прокат фіксує факт видачі фільму конкретному клієнту.
Оплата здійснюється за кожен оформлений прокат.

Зв'язки 
1. Фільм — Категорія
Тип: Один до багатьох (1:N).

Опис: Одна категорія (наприклад, "Комедія") може містити багато фільмів. На схемі лінія йде від category_id (PK) до таблиці Фільм.

Порада: У таблиці Фільм варто явно додати поле category_id (FK), щоб зв'язок був коректним.

2. Фільм — Кіноактор
Тип: Один до багатьох (1:N).

Опис: Один фільм може мати багато записів у таблиці Кіноактор (багато акторів, що в ньому знялися). Зв'язок іде від Ідентифікатор фільму (PK) до ідентифікатор фільму (FK).

3. Актор — Кіноактор
Тип: Один до багатьох (1:N).

Опис: Один актор може бути пов'язаний з багатьма записами в таблиці Кіноактор (зніматися в багатьох фільмах). Зв'язок іде від actor_id (PK) до ідентифікатор актора (FK).

Разом (Фільм — Кіноактор — Актор): Ці два зв'язки разом створюють відношення Багато до багатьох (M:N) між фільмами та акторами.

4. Фільм — Оренда
Тип: Один до багатьох (1:N).

Опис: Один конкретний фільм може бути орендований багато разів різними клієнтами в різний час. Зв'язок іде від Ідентифікатор фільму (PK) до FilmID (FK).

5. Фільм — Відгук
Тип: Один до багатьох (1:N).

Опис: На один фільм може бути залишено багато відгуків від різних користувачів. Зв'язок іде від Ідентифікатор фільму (PK) до ідентифікатор_фільму (FK).

6. Клієнт — Оренда
Тип: Один до багатьох (1:N).

Опис: Один клієнт може здійснювати багато оренд. Зв'язок іде від Ідентифікатор клієнта (PK) до Ідентифікатор клієнта (FK).

7. Клієнт — Відгук
Тип: Один до багатьох (1:N).

Опис: Один клієнт може написати багато відгуків (на різні фільми). Зв'язок іде від Ідентифікатор клієнта (PK) до ідентифікатор_клієнта (FK).

8. Оренда — Оплата
Тип: Один до одного (1:1) або Один до багатьох (1:N).

Опис: Кожна оренда має бути оплачена. На схемі зв'язок іде від Ідентифікатор оренди (PK) до Ідентифікатор оренди (FK) у таблиці Оплата. Зазвичай це 1:1 (одна оренда — один чек), але якщо можлива оплата частинами, то 1:N.

Висновок: у ході виконання роботи було спроектовано реляційну модель бази даних для системи автоматизації прокату фільмів. На основі аналізу предметної області була розроблена інфологічна схема, що включає ключові сутності: фільми, категорії, клієнти, актори, процеси оренди та оплати.
